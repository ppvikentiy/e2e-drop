# VDE2-5pr

E2E Drop Encryption, формат VDE2-5pr. Браузер отправителя шифрует содержимое файлов раздачи и запечатывает её описание (имена, типы, размеры, миниатюры). Сервер хранит шифртекст и запечатанное описание и ключей не получает.

English edition: [VDE.md](VDE.md). Реализация: [`vde2.js`](vde2.js). Тесты: `client/test/vde2.test.js` (команда `npm test` в каталоге `client/`), серверная проверка запечатанного описания — `server/test/manifest.test.js`.

VDE1 и VDE2 с открытым описанием не поддерживаются.

Авторы публикуют этот код и не предоставляют публичный сервис; каждый экземпляр эксплуатирует его оператор на собственную ответственность (см. `NOTICE` в корне репозитория).

## Ключ ссылки

Каждая раздача имеет ключ ссылки длиной 256 бит (`KEY_BYTES = 32`) из CSPRNG. Он переносится только во фрагменте URL:

```
https://хост/<токен>#<ключ>
```

`<ключ>` — base64url без `=`, 43 символа. Вход, который не декодируется ровно в 32 байта, отклоняется.

## Главный ключ

Главный ключ (32 байта) выводится HKDF-SHA-256 с пустой солью. `<dropId>` — UUID раздачи, присвоенный сервером.

| Случай | IKM | Info |
| --- | --- | --- |
| Без пароля | ключ ссылки | `VDE2/master/nopw\|<dropId>` |
| С паролем | ключ ссылки ‖ ключ пароля | `VDE2/master/pw\|<dropId>` |

Ключ пароля — `PBKDF2-HMAC-SHA-256(P, salt, iterations, 32 байта)`. `P` — пароль после NFKC в UTF-8, пробелы не обрезаются. Длина пароля — не менее 8 кодовых точек. `salt` — 16 случайных байт на раздачу, `iterations` — 600 000 по умолчанию. Получатель отклоняет значения вне 100 000…10 000 000. Соль и число итераций открыты.

## Производные ключи

Из главного ключа, HKDF-SHA-256, пустая соль:

| Назначение | Info | Тип |
| --- | --- | --- |
| Файл | `VDE2/file\|<dropId>\|<fileId>` | AES-256-GCM |
| Миниатюра файла | `VDE2/thumb\|<dropId>\|<fileId>` | AES-256-GCM |
| Печать описания | `VDE2-5pr/manifest\|<dropId>` | AES-256-GCM |
| Пропускной токен | `VDE2/gate\|<dropId>` | 32 байта, только при пароле |

## Сегменты

Содержимое файла делится на сегменты по `SEG = 4 МиБ` открытого текста; последний может быть короче. Пустой файл занимает один сегмент. Каждый сегмент шифруется AES-256-GCM ключом файла:

- Nonce, 12 байт: четыре байта `0x00`, затем номер сегмента как big-endian `uint64`. Повтор невозможен: у каждого файла каждой раздачи свой ключ.
- AAD: UTF-8 строки `VDE2/seg|<dropId>|<fileId>|<номер>|<число сегментов>`.
- Шифртекст: открытый текст и 16-байтовая метка.

Подмена бита, перестановка, повтор, удаление или добавление сегмента, перенос сегмента из другого файла или другой раздачи и укорачивание файла приводят к ошибке проверки метки.

```
ciphertextLength(n) = n + 16 * max(1, ceil(n / SEG))
```

Сегмент `i` занимает в шифртексте байты `[i * (SEG + 16), min((i + 1) * (SEG + 16), ciphertextLength(n)))`. Получатель запрашивает их с HTTP Range.

## Описание раздачи (manifest)

JSON в канонической форме, запечатываемый до отправки из браузера: ключи объектов отсортированы, без незначащих пробелов, UTF-8, допускаются только строки, целые числа, `true`/`false`, `null`, массивы и объекты.

```json
{"dropId":"…","files":[{"id":"…","name":"…","segments":1,"size":0,"thumb":null,"type":"…"}],"kdf":null,"segmentSize":4194304,"v":"VDE2-5pr"}
```

- `kdf` — `null` или `{"alg":"PBKDF2-SHA-256","iterations":…,"salt":"…"}`.
- `segments` равно `max(1, ceil(size / segmentSize))`.
- В `name` слэши и управляющие символы заменены на `_`, длина не более 200 символов; `type` — `тип/подтип` либо `application/octet-stream`.
- `thumb` — `null` или base64 от `nonce (12 байт) ‖ AES-256-GCM(data:-URL JPEG)` ключом миниатюры, AAD `VDE2/thumb|<dropId>|<fileId>`, nonce случайный.

Печать: `sealed = nonce (12 случайных байт) ‖ AES-256-GCM(ключ печати, nonce, байты описания, AAD = "VDE2-5pr/manifest|<dropId>")`. Браузер передаёт её в base64; сервер проверяет только правдоподобие (длина 30 байт … 2 МиБ) и хранит без изменений. Сервер регистрирует только число файлов и размеры их шифртекста.

Получатель вскрывает печать (метка GCM подтверждает подлинность) **до** использования любых данных описания, затем разбирает его и сверяет каноническую форму, версию, `dropId`, размер сегмента, число сегментов и параметры пароля, а также число файлов и `ciphertextLength(size)` каждого файла с тем, что сообщает сервер. При любом несоответствии выводится «Ошибка расшифровки. Проверьте правильность ссылки» (с паролем — «…ссылки и пароля»), данные не показываются.

## Пропускной токен

Только при пароле. Токен (base64url) получает сервер при проверке, в базе хранится его SHA-256 (hex). Неверные токены замедляют следующие попытки по паре «раздача + IP» и по IP. Токен выведен из главного ключа, поэтому по его хэшу пароль не подобрать без ключа ссылки.

## Наблюдаемое сервером

Сервер видит число файлов, размеры их шифртекста (по которым можно оценить размеры открытого содержимого), запечатанное описание, сроки, лимит и счётчик скачиваний, а при пароле — его соль, число итераций и хэш пропускного токена. Сервер не видит ключ ссылки, пароль, главный и производные ключи, имена и типы файлов, миниатюры и открытое содержимое. Время загрузки не записывается.

## Модель угроз

VDE2-5pr обеспечивает конфиденциальность содержимого и метаданных (имён, типов, миниатюр) по отношению к оператору, объектному хранилищу и стороне, получившей хранимые записи, а также обнаружение подмены содержимого и описания. Число файлов и размеры шифртекста остаются видимыми. Конфиденциальность не сохраняется для стороны, получившей полную ссылку и (если задан) пароль, и в отношении подменённого веб-приложения, читающего ключ в браузере. Офлайн-подбор пароля возможен для стороны, получившей шифртекст и описание мимо сервера и знающей ссылку; от него защищают длина пароля и стоимость PBKDF2.
