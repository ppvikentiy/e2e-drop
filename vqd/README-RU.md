# VQD

E2E QR Drop. Односторонняя передача файла анимированной последовательностью символов QR. Дисплей излучает последовательность. Камера принимает её. Канал не имеет сетевого пути и обратного пути. Предел формата — 512 МиБ. Эксплуатационная граница для версии 2 не измерялась заново (версия 1: приблизительно 150 МиБ).

Настоящий каталог содержит эталонный кодек. Реализация выполнена на JavaScript без зависимостей и исполняется на Node.js версии 20 и новее, а также в браузерах. Кодек не выполняет отрисовку и сканирование символов QR. Он выдаёт и принимает одну байтовую строку на кадр. Раскладка байтов определена в [SPEC-RU.md](SPEC-RU.md).

English edition: [README.md](README.md), [SPEC.md](SPEC.md). Лицензия: Apache-2.0, [LICENSE](LICENSE).

```js
import { createSender, fromBytes, Receiver } from 'vqd';

const sender = await createSender({
  source: fromBytes(bytes),
  name: 'photo.jpg',
  mime: 'image/jpeg',
});

// Каждый кадр — символ QR (байтовый режим, коррекция ошибок L). Последовательность повторяется.
const frame = await sender.nextFrame(); // Uint8Array, длина не более 2953

const receiver = new Receiver();
const info = await receiver.push(scannedBytes); // произвольные порядок, потери и смещение старта
if (receiver.complete) save(receiver.manifest.name, receiver.result());
```

Для объекта большого размера `Receiver` принимает `SymbolStore` и приёмник сегментов (OPFS или IndexedDB в браузере), вследствие чего передача не удерживается в оперативной памяти. На стороне отправки `Blob` оборачивается функцией `fromBlob`.

## Свойства

- Потеря, повтор и перестановка кадров допускаются. Приёмник может подключиться с произвольного кадра.
- Накладные расходы составляют приблизительно 1,01–1,05 от идеального числа кадров (`npm run bench:overhead`).
- Каждый сегмент проверяется SHA-256. Сегмент, не прошедший проверку, отбрасывается и собирается повторно.
- Обе конечные точки поддерживают возобновление. Одинаковые входные байты порождают одинаковый манифест и одинаковый 6-байтовый идентификатор файла.
- Версия 2 сжимает каждый сегмент gzip, если это экономит не менее 5 %, шифрует данные и имя файла по необязательному паролю (PBKDF2-HMAC-SHA-256, AES-256-GCM) и определяет цветной режим из трёх кодов на экране. Она несовместима с версией 1.

## Разработка

```
npm test
npm run bench:overhead
node --max-old-space-size=4096 bench/large.js 150 0.05
```

Третья команда выполняет передачу объёмом 150 МиБ при доле потерь кадров 0,05. Эталонный прогон при размере кадра 2953 байта использовал 27 сегментов, приблизительно 1,053 от идеального числа кадров, и совпал с источником побайтово.

Публичные экспорты определены в `src/index.js`: кодек кадров, фонтанные кодер и декодер, таблица степеней, CRC-16, ГПСЧ, `createSender` и `Receiver`.
