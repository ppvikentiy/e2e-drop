# E2E Drop

Программное обеспечение для самостоятельного размещения: передача файлов со сквозным шифрованием и без создания учётных записей.

Клиент выполняет шифрование содержимого каждой раздачи до передачи на сервер (формат VDE2-5pr). Сервер сохраняет шифртекст в S3-совместимом бакете. Имена, медиатипы, размеры и миниатюры файлов также шифруются: они лежат в запечатанном описании раздачи, которое сервер прочитать не может. PostgreSQL хранит хэши, запечатанные описания, размеры шифртекста и служебные записи. IP-адреса клиентов не журналируются, поисковые системы к сайту не допускаются. URL раздачи имеет вид `https://хост/<токен>#<ключ>`, где `<токен>` состоит из 43 символов. Ключ размещается во фрагменте URL и в HTTP-запросы не включается.

English edition: [README.md](README.md).

## Предельные значения

- Максимальное число файлов в одной раздаче: 10.
- Максимальный размер одного файла: 500 МБ.
- Срок хранения, отсчитываемый от публикации: 1, 3, 7 или 30 суток.
- Лимит скачиваний: 1, 5, 10 либо целое число в диапазоне 1..1000.
- Пароль: необязателен, не короче 8 символов. Входит в вывод ключей и на сервер не передаётся. До принятия пропускного токена, выведенного в браузере, тело ответа API содержит только `requiresPassword`, идентификатор раздачи и параметры PBKDF2. Описание раздачи и ключ доступа не возвращаются.
- Несколько файлов извлекаются по отдельности либо собираются в ZIP в браузере получателя. Одиночный файл поддерживает HTTP Range.
- Миниатюры изображений и видео представляют собой объекты JPEG размером не более 40 КБ. Они формируются в браузере отправителя, шифруются и включаются в описание раздачи. Отображение миниатюры счётчик скачиваний не увеличивает.
- Отправитель может удалить раздачу сразу. Секрет загрузки остаётся в браузере около 6 часов: на странице после публикации и при следующем открытии.
- В Chrome на Android отправка продолжается после закрытия приложения (Background Fetch). Ссылка показывается при следующем открытии.

Раздачи с истёкшим `expires_at` и раздачи с `download_count >= max_downloads` удаляются из объектного хранилища и из базы данных задачей с периодом 10 минут. Удаление откладывается на 24 часа после `last_download_at`, что допускает завершение прерванного запроса Range.

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/home` | Начальная страница. `GET /` возвращает перенаправление на `/home`. В автономном режиме отображения клиент заменяет `/home` на `/upload`, если навигатор сообщает о наличии сети. |

| `/p/<код>` | URL сопряжения, закодированный в этом символе. Клиент заменяет путь на `/upload?pair=<код>` и сохраняет фрагмент. |
| `/offline` | Оптическая передача без сети. Передача: `/offline/send`. Приём: `/offline/receive`. |

| `/faq` | Ответы на вопросы о сервисе: отправка, ссылка, срок, передача на компьютер и через QR. |

Вне автономного режима отображения маршруты `/upload`, `/receive`, `/offline` (включая дочерние) и `/<токен>` не отображаются до фиксации состояния согласия `accepted`. Значение хранится в `localStorage` по ключу `vd-consent`. В автономном режиме элемент согласия не выводится.

Идентификаторы оформления: `dark`, `light`, `simple`. Значение `simple` задаёт увеличенный кегль, отключение анимации, пошаговые подписи и видимую обводку основного действия. Выбор хранится по ключу `vd-theme`. При отсутствии сохранённого значения `prefers-color-scheme: light` выбирает `light`; в остальных случаях клиент выбирает `dark`.

Предпочтение гарнитуры хранится отдельно по ключу `vd-font`. Значение `dyslexia` включает Andika и не меняет оформление. Без этой записи клиент использует Roboto и JetBrains Mono.

Язык интерфейса — русский. Оформление по умолчанию — тёмная моноширинная вёрстка. В сборку клиента включены гарнитуры JetBrains Mono и Inter.

## Шифрование

Раздачи, создаваемые опубликованным клиентом, шифруются в браузере отправителя. Формат — VDE2-5pr. Спецификация: [client/src/crypto/VDE-RU.md](client/src/crypto/VDE-RU.md). English edition: [client/src/crypto/VDE.md](client/src/crypto/VDE.md). Реализация: `client/src/crypto/vde2.js`. Команды тестирования: `cd client && npm test`, `cd server && npm test`. Прежние форматы (VDE1 и VDE2 с открытым описанием) больше не поддерживаются: такие раздачи не выдаются, их открытые метаданные стираются при обновлении, сами раздачи удаляются по сроку.

- Ключ ссылки: 256 бит, CSPRNG, одно значение на раздачу. Кодирование: base64url без дополнения (43 символа). Размещение: фрагмент URL после `#`.
- Главный ключ: HKDF-SHA-256 от ключа ссылки с привязкой к идентификатору раздачи. При пароле к ключу ссылки перед HKDF присоединяется `PBKDF2-HMAC-SHA-256` пароля (600 000 итераций, 16 байт соли на раздачу).
- Из главного ключа HKDF выводит ключ AES-256-GCM на каждый файл, на миниатюру каждого файла, ключ AES-256-GCM, которым запечатывается описание, и, при пароле, пропускной токен.
- Содержимое файлов закрывается сегментами по 4 МиБ AES-256-GCM. Nonce — номер сегмента; AAD связывает идентификаторы раздачи и файла, номер сегмента и число сегментов.
- Имена, медиатипы, размеры открытого содержимого и миниатюры образуют каноническое JSON-описание, которое браузер отправителя запечатывает AES-256-GCM (случайный nonce 12 байт, AAD привязан к идентификатору раздачи). Сервер хранит запечатанные байты, не имея возможности их прочитать; любое изменение не открывается в браузере получателя, который также сверяет число файлов и размеры шифртекста, сообщённые сервером.
- Service worker получателя запрашивает шифртекст с HTTP Range, расшифровывает сегменты по 4 МиБ и может сформировать ZIP средствами `client-zip`. Если worker не управляет страницей, расшифрование выполняется в памяти страницы.

Пароль на сервер не передаётся. Для ограничения попыток браузер передаёт пропускной токен, выведенный из главного ключа; сервер хранит его SHA-256 и задерживает повторные неверные токены по паре «раздача + IP». `POST /api/drops` отклоняет параметры пароля при наличии `pairCode`: ключ ссылки уже присутствует во фрагменте URL сопряжения.

Отсутствие фрагмента (или пароля, если он задан) исключает расшифрование; при отсутствующем, обрезанном или неверном ключе страница выводит единое сообщение. Обладание полным URL и паролем достаточно для расшифрования. Подменённое клиентское приложение может прочитать ключ в браузере. Установка PWA и воспроизводимая сборка снижают подверженность подмене отдаваемого приложения. Раскрытие базы данных или бакета раскрывает число файлов и размеры шифртекста, но не имена, типы и открытое содержимое.

## Сопряжение

`/receive` — страница сопряжения для узла, не использующего камеру. Страница выполняет `POST /api/pair` и отображает код вида `K7M-4QX-9TD` и символ QR с полезной нагрузкой `/p/<код>#<ключ>`. Узел формирует ключ ссылки и помещает его только во фрагмент.

Отправляющий клиент открывает этот URL, шифрует ключом из фрагмента и передаёт раздачу с полем `pairCode` в `POST /api/drops`. Принимающий узел опрашивает `GET /api/pair/:code/status` с заголовком `X-Pair-Secret`. В состоянии `ready` узел переходит на `/<токен>#<ключ>`.

- Алфавит кода: Crockford base32, длина 9, энтропия 45 бит. Регистр и символы-разделители при нормализации отбрасываются. Хранимое значение — `SHA-256` от префикса `pair:`, соединённого с нормализованным кодом.
- Срок до присоединения: 10 минут. Срок после присоединения: равен сроку незавершённой раздачи, 6 часов. Открытый токен сохраняется для получения не дольше 15 минут, после чего строка сопряжения удаляется.
- Неуспешные проверки кода: 20 за 15 минут с одного IP-адреса. Создание кодов: 30 в час с одного IP-адреса.

## Оптическая передача

Один файл размером не более 512 МиБ передаётся последовательностью символов QR с дисплея на камеру. Канал не имеет сетевого пути и обратного пути. Кодек — пакет `vqd`. Описание: [vqd/README-RU.md](vqd/README-RU.md). Формат: [vqd/SPEC-RU.md](vqd/SPEC-RU.md). English editions: [vqd/README.md](vqd/README.md), [vqd/SPEC.md](vqd/SPEC.md). Эксплуатационная граница версии 2 заново не измерялась (версия 1: порядка 150 МиБ).

Отправитель выбирает версию QR 40, 30 или 20 и частоту кадров в диапазоне 5..30 кадров в секунду. Получатель декодирует средствами zxing-wasm в worker и записывает принятые байты в OPFS. Приём сохраняется при перезагрузке страницы. На устройстве удерживается одна незавершённая передача. Каждый сегмент проверяется SHA-256. Потеря, повтор, перестановка кадров и позднее подключение допускаются фонтанным кодом.

При установке service worker выполняет предварительное кэширование оболочки приложения, включая декодер WebAssembly. После одной загрузки при наличии сети оптические маршруты функционируют без сети. Доступ к камере ограничен заголовком `Permissions-Policy: camera=(self)`. Отправитель может задать пароль (не короче 8 знаков): тогда данные и имя файла шифруются в браузере (AES-256-GCM, ключ из PBKDF2-HMAC-SHA-256), а пароль нигде не сохраняется. Без пароля камера, наблюдающая дисплей, получает файл. Сегменты сжимаются gzip, когда это выгодно, а отправитель может показывать по три кода на экране в красном, зелёном и синем каналах. Перед приёмом получатель проверяет свободное место (1,1 размера файла).

## Установленное приложение

Сайт является прогрессивным веб-приложением. Если браузер предоставляет запрос на установку, подвал отображает соответствующий элемент управления. На iOS подвал фиксирует последовательность Safari: «Поделиться», затем «На экран Домой».

После установки цель общего доступа Android доставляет файлы на `/upload`. Service worker обрабатывает `POST /share-target`. Если worker ещё не управляет клиентом, сервер отвечает на этот URL перенаправлением на `/upload`.

При сообщении навигатора об отсутствии сети оболочка отдаётся из кэша, а информационная полоса содержит ссылку на оптическую передачу. Ответы API и тела файлов в кэш не помещаются. Ответы документов используют `Cache-Control: no-cache`. Файлы в `/assets/` кэшируются как неизменяемые в течение одного года. `sw.js` и веб-манифест используют `Cache-Control: no-cache`.

Поля манифеста `handle_links` и `launch_handler` запрашивают открытие URL Drop в установленном приложении на Android и в настольном Chromium. Safari на iOS для веб-приложений это поведение не реализует.

## Идентификация сборки

Подвал отображает версию из `client/package.json`, тип сборки (`release` или `dev`), номер сборки и, при наличии, краткий идентификатор коммита. Номер берётся из `BUILD_NUMBER`, иначе из `client/build-info.json` (файл записывает `deploy.ps1` при наличии git), иначе из `git rev-list --count HEAD`, иначе из метки времени UTC вида `YYYYMMDD.HHMM`. Тип равен `release` для производственной сборки Vite и `dev` в остальных случаях, если не задана переменная `BUILD_TYPE`. Идентификатор коммита берётся из `GIT_SHA`, иначе из того же JSON-файла, иначе из `git rev-parse --short HEAD`.


| Каталог | Содержимое |
| --- | --- |

Байты объекта передаются через API в бакет потоком. Файловая система сервера копию не сохраняет. Пароли сервер не получает. Для раздачи с паролем база данных хранит соль и число итераций PBKDF2 и SHA-256 пропускного токена.

## Развёртывание с Windows

Входные условия: VPS под управлением Ubuntu или Debian с доступом по SSH, S3-совместимый бакет и, при необходимости, домен, A-запись которого разрешается в адрес сервера. На узле оператора требуются Windows 10 или Windows 11 и клиент OpenSSH.

`deploy\deploy.bat` принимает конечную точку SSH, необязательные домен и адрес электронной почты для Let's Encrypt, а также endpoint, регион, имя бакета и учётные данные S3. Пустые домен и адрес электронной почты оставляют сервис доступным по IP-адресу.

Скрипт проверяет SSH. Аутентификация по паролю приводит к установке ключа `%USERPROFILE%\.ssh\e2e_drop_deploy_ed25519`. Затем скрипт передаёт дерево файлов и выполняет `deploy/install.sh`. Установщик разворачивает nginx, PostgreSQL и Node.js. Node.js 22 устанавливается, если текущая мажорная версия ниже 20. Роль базы данных создаётся только при отсутствии. Выполняется сборка клиента. Проверяются запись в бакет и удаление из бакета. Устанавливается unit systemd `e2e-drop`. Записывается сайт nginx `e2e-drop`. При заданных домене и адресе электронной почты сертификат запрашивается командой `certbot certonly --nginx --keep-until-expiring`. Сертификат, находящийся внутри срока действия, не заменяется.

Повторное выполнение применяет изменения и сохраняет существующие пароль базы данных и `APP_SECRET`. Конфигурация nginx, которой управляет установщик, ограничена сайтом `e2e-drop`. Заданный домен не устанавливает `default_server`. Обслуживание по IP-адресу устанавливает `default_server` только при отсутствии этого флага у другого сайта. Путь журнала установки: `/var/log/e2e-drop-install.log`. Собранные параметры, за исключением секретного ключа S3, сохраняются в `deploy/deploy.settings.json`.

```bash
systemctl status e2e-drop
journalctl -u e2e-drop -f
cat /opt/e2e-drop/.env
```

Политика жизненного цикла бакета должна прерывать незавершённые multipart-загрузки по истечении одних суток. В противном случае части загрузки, прерванной завершением процесса, остаются в бакете.

## Локальная разработка

Требования: Node.js версии 20.6 или новее, PostgreSQL и S3-совместимая конечная точка. MinIO удовлетворяет требованию к хранилищу.

```bash
cd server
cp .env.example .env
npm install
npm run check-s3
npm run dev
```

API принимает соединения на `http://127.0.0.1:3000`. Миграция схемы выполняется при старте процесса.

```bash
cd client
npm install
npm run dev
```

Интерфейс обслуживается по адресу `http://localhost:5173`. Запросы с префиксом `/api` проксируются на процесс API.

`server/.env.example` определяет `DATABASE_URL`, `APP_SECRET`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `S3_FORCE_PATH_STYLE`. `PORT` и `HOST` необязательны.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Тело ответа `{ ok: true }`. |
| `POST /api/drops` | Создаёт незавершённую раздачу. Тело JSON: `files` — массив `{ size }` (размер открытого содержимого, только для проверки пределов), `expiry` из множества `{1d, 3d, 7d, 30d}`, `maxDownloads`, необязательный `password` вида `{ salt, iterations }` (параметры PBKDF2, не сам пароль), необязательный `pairCode`. Возвращает `dropId`, секрет загрузки и по каждому файлу `{ id, size, cipherSize }`. Сохраняется только размер шифртекста. |
| `PUT /api/drops/:id/manifest` | Тело `{ sealed }`: запечатанное описание (base64, не более 2 МиБ); для раздачи с паролем — также `gateHash`. Сохраняется без чтения. Требуется `X-Upload-Secret`. |
| `GET /api/drops/:id/files/:fileId/status` | Возвращает число сохранённых байт. Требуется заголовок `X-Upload-Secret`. |
| `PUT /api/drops/:id/files/:fileId` | Записывает байты объекта. Частичная запись использует `Content-Range: bytes START-END/SIZE`. Тело, покрывающее объект целиком, передаётся потоком без этого заголовка. Требуется `X-Upload-Secret`. |
| `POST /api/drops/:id/finalize` | Публикует незавершённую раздачу и возвращает публичный токен. Требует сохранённого описания. Повторный вызов после публикации отвечает кодом 409. |
| `GET /api/d/:token` | Возвращает `dropId`, запечатанное описание, размер шифртекста каждого файла и ключ доступа; для раздачи с паролем — `{ requiresPassword: true, dropId, kdf }`. |
| `POST /api/d/:token/unlock` | Тело `{ gateToken }`. Проверяет пропускной токен (код 401 при неверном, 429 во время задержки) и возвращает то же, что `GET` для раздачи без пароля. |
| `GET /api/d/:token/files/:index` | Возвращает один объект шифртекста. Требуется заголовок `X-Access-Key`. Поддерживает HTTP Range. |
| `POST /api/pair` | Выделяет код сопряжения и секрет. |
| `GET /api/pair/:code/check` | Сообщает, находится ли код в состоянии `waiting`. |
| `GET /api/pair/:code/status` | Возвращает `waiting`, `uploading` или `ready` с токеном. Требуется заголовок `X-Pair-Secret`. |
| `DELETE /api/pair/:code` | Удаляет строку сопряжения. Требуется `X-Pair-Secret`. |
| `GET /api/site` | `{ locked, allowed }`: задан ли оператором пароль сайта и есть ли у браузера сессия. |
| `POST /api/site/login` | Тело `{ password }`. Устанавливает cookie сессии `vd_site` (30 суток). Не более 10 неверных паролей за 15 минут с одного IP. Пока сайт закрыт, прочие пути `/api`, кроме `/api/health`, отвечают 401 с причиной `site-locked`. |

API принимает только раздачи VDE2-5pr: пути для незашифрованного содержимого или открытых метаданных нет.

**Учёт скачиваний.** Открытие страницы или успешное снятие пароля возвращает ключ доступа: HMAC-SHA256 на ключе `APP_SECRET`, срок действия 24 часа, содержит случайный nonce. Клиент передаёт его в заголовке `X-Access-Key`, поэтому он не попадает в адреса и журналы доступа. Первый запрос, предъявляющий ранее не наблюдавшийся ключ, увеличивает `download_count` на единицу. Последующие запросы с тем же ключом в течение 24 часов, включая продолжение Range и дополнительные файлы, счётчик не увеличивают. К IP-адресу ключ не привязан.

**Продолжение загрузки.** Объекты размером более 5 МиБ передаются частями по 8 МиБ через multipart-загрузку S3. Сервер отклоняет нефинальную часть размером менее 5 МиБ и частичную часть размером более 32 МиБ. `PUT`, диапазон которого покрывает объект целиком, передаётся потоком при любом размере в пределах лимита раздачи и не буферизуется как одна часть. Если для этого объекта уже открыта multipart-загрузка, она прерывается до приёма потока. `PUT` файла, уже помеченного как загруженный, подтверждается как успех, а тело отбрасывается. Частичный `PUT`, начальное смещение которого не равно сохранённому `uploaded_bytes`, отвечает кодом 409 и текущим смещением. Клиент сохраняет `dropId`, секрет загрузки, ключ ссылки, выведенный главный ключ (удаляется при публикации) и смещения по файлам в IndexedDB (`vd-uploads`); пароль не сохраняется. После сбоя транспорта клиент возобновляет запись с сохранённого смещения. Повторное открытие документа при ещё существующей записи выводит запрос на продолжение при выборе тех же файлов. Незавершённая раздача, не прошедшая финализацию, истекает на сервере через 6 часов. Клиент удаляет записи IndexedDB, у которых `updatedAt` старше 7 часов.

**Гонка публикации.** Страница и service worker могут оба вызвать `POST /api/drops/:id/finalize`. Первый вызов, заставший `status = 'pending'`, публикует раздачу. Последующий вызов получает код 409. Вызвавший, получивший 409, читает токен из записи IndexedDB, которую записал победитель (`waitForReady`, тайм-аут 10 секунд).

**Фоновая отправка.** Путь используется только в Chrome на Android и только при наличии `BackgroundFetchManager`, управляющего service worker и origin-private file system, а также когда `navigator.storage.estimate` сообщает не менее `2 × длина шифртекста + 8 МиБ` свободной квоты. Страница шифрует каждый файл в OPFS, удерживая в памяти один сегмент, в каталог, удаляемый после публикации. Затем она передаёт по одному `PUT` целого объекта на файл через Background Fetch. Идентификатор регистрации равен `dropId`. Браузер может продолжить передачу после закрытия документа. По событию `backgroundfetchsuccess` service worker вызывает финализацию, удаляет каталог шифртекста и отправляет открытым окнам сообщение `vd-bg-ready`. По событию `backgroundfetchfail` заголовок уведомления устанавливается в строку сбоя. `backgroundfetchclick` открывает `/upload`. Если фоновую регистрацию начать нельзя, страница выполняет загрузку, пока документ открыт. Прочие агенты пользователя выполняют загрузку только при открытом документе.

**Заголовки ответа.** `Content-Security-Policy` разрешает `'wasm-unsafe-eval'` в `script-src` для декодера QR. Дополнительные заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin` и `Permissions-Policy` с `camera=(self)`. Ответы по HTTPS содержат `Strict-Transport-Security`. Ответы с шифртекстом имеют тип `application/octet-stream` и `Content-Disposition: attachment`; имя и тип восстанавливает браузер получателя после расшифрования. Встроенных скриптов на странице нет.

**Ограничения частоты, на один IP-адрес.** Создание раздач: 30 в час. Создание кодов сопряжения: 30 в час. Неверные пропускные токены: по паре «раздача + IP» 5 без задержки, далее задержка удваивается от 2 секунд до 15 минут; по всем раздачам — 30 в час с одного IP до той же задержки. Счётчики хранятся в памяти и сбрасываются через час без ошибок. Неуспешные проверки кода сопряжения: 20 за 15 минут. Запросы состояния сопряжения: 300 в минуту.

**Индексация и журналы.** Ни один путь не предназначен для поисковых систем. Каждый ответ содержит `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex`, кроме ответов ботам предпросмотра ссылок в мессенджерах: они получают страницу, чтобы вставленная ссылка показала карточку; `robots.txt` разрешает доступ только им. Карты сайта нет. Адрес картинки предпросмотра страница подставляет сама (`__ORIGIN__` в `index.html`), поэтому каждый экземпляр указывает на себя. Сценарий развёртывания настраивает nginx без журнала доступа и с журналом только критических ошибок; приложение адреса клиентов не записывает.
